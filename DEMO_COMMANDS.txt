TROUBLESHOOTING:
────────────────

  "Connection refused"
    → Make sure Terminal 1 is running: bash start_all.sh
    → Wait 3-5 seconds for services to start

  "Port 8501 not opening"
    → Streamlit takes 5-10 seconds to load
    → Check Terminal 1 logs for errors

  "Files not in /data/keeper*/"
    → Kill demo and re-run
    → Check database: sqlite3 tracker.db "SELECT * FROM files;"

  "Can't download file"
    → Make sure file is in "available" status (not degraded)
    → Check Cluster tab to see if keepers are healthy

  "Cluster shows 'down' nodes"
    → Normal\! Nodes have 3-second timeout
    → They recover automatically
    → See logs: tail -f /tmp/tracker.log

QUESTIONS TO EXPECT:
────────────────────

  Q: Why replicate data?
  A: If 1 server fails, you still have the data on another server

  Q: How does the system know a server is down?
  A: Heartbeat timeout - if no heartbeat for 3 seconds, marked as down

  Q: What happens during re-replication?
  A: System copies missing chunks to healthy servers - takes 1-2 seconds

  Q: Can multiple servers die and still recover?
  A: Yes\! With 2x replication, system survives 1 server failure
     With 3x replication, system survives 2 server failures

  Q: Why UDP instead of TCP?
  A: UDP allows resumable downloads - if connection drops,
     resume from last received packet instead of starting over

  Q: How do users access this?
  A: Web UI (http://localhost:8501) or REST API or Python client
